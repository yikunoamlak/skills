# Contextual Toolkit

This is the practical instrument library for the skill. Choose tools based on the kind of context that is uncertain. Do not use every tool on every project.

## A. Scale / composition tools

### 1. Context Ladder
**Use when:** the artifact feels isolated.

Map:
`thing → container → parent system → ecosystem → culture/place/time`

**Output:** what the parent system demands of the artifact.

### 2. Adjacency Map
**Use when:** relationships to neighboring elements matter.

List what is:
- above / below
- before / after
- inside / outside
- near / far
- primary / secondary
- dependent / independent

**Output:** hierarchy and spacing decisions.

### 3. Scale Test
**Use when:** size or viewing distance matters.

Test at:
- intended real size
- smaller than intended
- larger than intended
- realistic viewing distance

**Output:** what survives and what collapses.

## B. Human / behavior tools

### 4. Contextual Inquiry
**Use when:** assumptions about user behavior are risky.

Observe people doing the real activity in its normal environment. Capture work practice, interruptions, workarounds, tools, dependencies, and language. Contextual Design treats field data as a basis for system design. [1]

### 5. Before / During / After Map
**Use when:** the artifact is part of a sequence.

`before → encounter → interaction → result → after`

**Output:** hidden requirements at transitions.

### 7. Error / Misuse Map
**Use when:** people may misunderstand or misuse the design.

Ask:
- What could they reasonably think this means?
- What could they do accidentally?
- What would the design do in response?
- How can the design prevent or recover gracefully?

## C. System / ecosystem tools

### 8. Ecosystem Map
Map:

`people ↔ artifacts ↔ organizations ↔ platforms ↔ services ↔ physical environment`

Mark:
- dependency
- information flow
- physical flow
- money/resource flow
- responsibility
- failure points

### 9. Touchpoint Audit

| Touchpoint | User expectation | Current experience | Desired behavior | Consistency | Priority |
|---|---|---|---|---|---|
| | | | | | |

**Use for:** brands, campaigns, services, products, apps, websites, exhibitions.

### 10. Service Blueprint
Map customer actions, frontstage actions, backstage actions, support processes, and physical/digital evidence. Use when the artifact is one visible touchpoint in a larger service. [2]

### 11. Dependency Map
Ask:
- What does this design depend on?
- What depends on this design?
- What breaks if it changes?
- Which constraints are upstream?

## D. Visual / perceptual tools

### 12. Gestalt Relationship Audit
For every major grouping ask:
- Why are these items perceived as a group?
- Proximity?
- Similarity?
- Common region?
- Connectedness?
- Continuity?
- Closure?
- Figure-ground?
- Common fate in motion?

Use it to diagnose why a composition feels chaotic or unexpectedly grouped. [3][4]

### 13. Attention Map
Draw the likely order of attention:

`1 → 2 → 3 → 4`

Then compare with intended priority.

**Use for:** posters, ads, landing pages, dashboards, exhibition panels, title cards, presentations.

### 14. Contrast / Hierarchy Ladder
Rank:

`primary → secondary → tertiary → metadata → decoration`

Test size, weight, contrast, position, density, and motion against that hierarchy.

## E. Information / interaction tools

### 15. Information Architecture Map
Map:

`home/entry → sections → pages/states → related content → search/navigation`

Ask whether labels and organization match user mental models. IA is concerned with organization, labeling, navigation, search, and findability. [5]

### 16. UX Planes Check

`strategy → scope → structure → skeleton → surface`

When the complaint is "make it prettier," inspect the lower planes before changing surface styling. [6]

### 17. Action Loop Audit

`discover → act → feedback → interpret → continue`

For every important interaction, ask:
- Can the user discover the action?
- Is the mapping understandable?
- Is the system state visible?
- Is feedback timely and meaningful?
- Are errors preventable or recoverable?

Use Norman's concepts of affordances/signifiers, mapping, feedback, constraints, and conceptual models. [7]

## F. Motion / time tools

### 19. Sequence Strip
Create a strip of frames/shots/states:

`A → B → C → D → E`

Annotate each transition with:
- attention
- emotion
- information
- motion
- sound
- continuity

**Use for:** films, title sequences, ads, reels, UI animation, presentations, onboarding.

### 20. Motion Function Test
For each animation classify the purpose:
- orientation
- continuity
- feedback
- emphasis
- narrative
- delight
- atmosphere

If there is no credible function, question the motion.

### 21. Timing / Attention Curve
Map attention over time and compare it with message importance.

## G. Physical / spatial tools

### 22. Site Context Map
Map:
- sun
- wind
- heat
- views
- noise
- movement
- entrances
- existing structures
- vegetation
- water/drainage
- public/private edges
- local materials
- cultural patterns

Use for architecture, installations, exhibitions, wayfinding, outdoor graphics.

### 23. Movement / Threshold Map
Map:

`approach → threshold → orientation → movement → destination → departure`

Useful for buildings, shops, museums, events, signage, retail, and wayfinding.

### 24. Human Scale Test
Evaluate from realistic standing, sitting, walking, reaching, reading, and viewing positions.

## H. Brand / communication tools

### 25. Touchpoint Spectrum
Map all places the identity appears:

`awareness → consideration → purchase/use → support → retention → advocacy`

Test recognition and consistency across each point.

## I. Production / lifecycle tools

### 27. Real-Production Test
Replace design-board conditions with:
- actual stock/material
- actual screen
- actual printer
- actual device
- actual sound system
- actual physical scale
- actual data/content

### 28. Lifecycle Map

`make → distribute → encounter → use → maintain → update → repair → reuse → retire`

Ask how design decisions change across the lifecycle.

## J. Decision / research tools

### 30. Evidence-to-Decision Chain
Use:

`evidence → contextual interpretation → design implication → decision → test`

This prevents "I think this looks better" from being mistaken for a design rationale.

### 31. Forces Map
Use when several legitimate goals conflict.

`forces → priority → trade-off → solution`

### 32. Precedent Comparison
For each reference, record:

- What context made it successful?
- What is transferable?
- What is not transferable?
- Which contextual difference could break the precedent?

Never copy the visible form while discarding the conditions that produced it.

### 33. In-Situ Prototype
Place/operate the design in its real or simulated environment as early as possible.

A prototype that works only on the designer's board is incomplete evidence.

## Tool-selection matrix

| Uncertainty | Primary tool |
|---|---|
| What larger system does this belong to? | Context Ladder |
| What surrounds it? | Adjacency Map |
| Who uses it in reality? | Contextual Inquiry |
| What happens before/after? | Before/During/After Map |
| Why does the composition feel unclear? | Gestalt Audit + Attention Map |
| Why is a UI confusing? | Action Loop + State Matrix + IA Map |
| Is the page problem deeper than styling? | UX Planes Check |
| How does the brand behave across outputs? | Touchpoint Audit + Constant/Variable Matrix |
| How should a film/title sequence behave? | Sequence Strip + Motion Function Test |
| How should a building respond to place? | Site Context Map + Movement/Threshold Map |
| What happens after launch/use? | Lifecycle Map |
| Why does a good design fail in production? | Real-Production Test |
| Which direction is best under conflict? | Forces Map + Evidence-to-Decision Chain |
